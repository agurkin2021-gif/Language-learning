# Защита маршрута CARD INBOX: что работает и что ещё нужно

Дата: 2026-10-30. Единственный репозиторий: `agurkin2021-gif/Language-learning`.

## Текущая проверенная архитектура

Запрос владельца `CARD:` в GitHub Issue → `.github/workflows/card-inbox.yml` (`main`) → `live-content/scripts/card_inbox.py` → **только** `live-content/content/{papa,mama,dima}/cards-{es,en}.json`.

Применены: проверка автора Issue, явные профили/языки, строгая схема, нормализация Unicode, устойчивые ID, защита повторов и удалённых записей, сверка с архивом освоенного, тесты, повторная загрузка свежей ветки при конкурирующем обновлении, подтверждение фактического содержимого удалённой ветки. Прямые изменения карт отслеживает `.github/workflows/card-bypass-watchdog.yml` из `live-content`.

**Текущий режим безопасной блокировки:** новый элемент НЕ публикуется, если канонический архив соответствующего профиля/языка пуст (`ARCHIVE_NOT_READY`). Уже опубликованные элементы могут быть повторно признаны существующими, без добавления дублей. Этот режим нужен, потому что пустой файл не доказывает отсутствие освоенных слов на телефоне.

Полный архив заполняет только `PrivateVocabularySync` из Android. Он хранит `mastered` и `deleted`, но **не** должен заменяться списком новых карточек.

## Не сделано автоматически — GitHub-права и Rulesets

По текущему подключению GitHub можно читать Rulesets, но нельзя их создавать или менять. При проверке существующих правил API вернул `[]`. GitHub-операции `create_file`/`update_file` по-прежнему доступны сторонним агентам с разрешениями репозитория. **Инструкции и watchdog не равны запрету записи.**

Администратор репозитория может открыть `Settings → Rules → Rulesets`. **Для ветки `main`** безопасно включить запрет удаления и force-push, обязательный pull request для изменений и отдельную проверку workflow перед слиянием (следить, чтобы PR workflow продолжал существовать). Это защищает код автоматики от случайной прямой правки.

**Не вводить требование Pull Request / Restrict updates для `live-content` без миграции мобильной синхронизации.** Android сейчас напрямую записывает в `live-content/content/<profile>/vocabulary-<language>.json` по GitHub token. Ограничение всей ветки может сломать синхронизацию освоенных карточек, удалений и прогресса, а также STORY INBOX и CARD INBOX.

Для настоящей невозможности обойти CARD INBOX нужны:
1. Отдельная роль/установка GitHub App для приёмной карточек. У ChatGPT больше нет GitHub Contents:write к `live-content`; разрешены только Issue.
2. Перевод записи полного словаря Android на обособленный доверенный путь/ветку либо отдельный проверенный шлюз с правами на запись, с тестированием и выпуском нового APK (без потери существующей SQLite).
3. После миграции — Ruleset `Restrict updates`/обязательная проверка для `live-content` с обходом только для доверенной службы записи; отдельно проверить, что пользовательский GitHub Connector не может обойти правило.
4. Отдельный отрицательный тест: попытка `update_file` в `cards-*.json` должна отклоняться самим GitHub; тестовые карточки не удалять и личные архивы не сбрасывать.

До выполнения этих шагов **не утверждать, что прямой обход технически невозможен**.

## Проверка результата каждой заявки

Создание Issue — не публикация. Считать завершённой только заявку, которую workflow закрыл с комментарием `Card inbox accepted`, результатом `VERIFIED`, а ожидаемые карточки читаются из правильной удалённой ветки. `Card inbox rejected` означает отказ без публикации. `ARCHIVE_NOT_READY` требует сначала успешной синхронизации полного словаря с Android.

Устанавливаемое Android-приложение не обновляется при изменениях GitHub-фидов/Workflow; обновление APK понадобится только для переноса механизма синхронизации из Android на другой канал.
