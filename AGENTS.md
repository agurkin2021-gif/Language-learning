# ЕДИНСТВЕННЫЙ ПУТЬ ДЛЯ РАССКАЗОВ — STORY INBOX

**При любой команде «добавь/отправь рассказ» создавай ровно ОДНУ заявку GitHub Issue.**
Репозиторий: `agurkin2021-gif/Language-learning`. В GitHub Connector
вызывай `create_issue` с названием `STORY: <title>` и телом из **ОДНОГО JSON**,
без Markdown и без обрамляющих кавычек.

Обязательные поля JSON:
```json
{
  "profile": "papa",
  "language": "es",
  "title": "Un día",
  "spanish": "Hola. Chau.",
  "russian": "Привет. Пока."
}
```
`profile` строго `papa|mama|dima`; `language` строго `es|en`.
При EN английский текст также помещается в поле `spanish`, согласно текущей
схеме SQLite. Русский перевод обязателен. Можно передать `id`, если известен.
Не гадать профиль/язык, когда из контекста нельзя однозначно установить их.
Не класть в публичную заявку приватные данные, токены, словарь, прогресс.

**НЕЛЬЗЯ ПИСАТЬ В STORY FEED НАПРЯМУ.** GitHub Actions
`.github/workflows/story-inbox.yml` из default-ветки `main` принимает только
заявки с префиксом `STORY:`, созданные владельцем репозитория; сам вызывает
`live-content/scripts/story_inbox.py add`, валидирует и пишет ТОЛЬКО
`live-content/content/stories.json` (единый файл для всех профилей/языков).
Проверки: schema, лимиты, совпадение количества Android TTS фрагментов с
переводом, уникальность, идемпотентность. Заявка закрывается после успеха.
Если Action не запустилась или упала, НЕ утверждать «рассказ добавлен».

**СТРОГО ЗАПРЕЩЕНО** помещать новые рассказы в
`content/live_content.json`, `content/papa/stories-es.json`,
`content/<profile>/stories-<language>.json`, `content/stories-es.json`,
`main` или `codex/android-v1`. Старые файлы используются только
старыми версиями APK, но не являются входами новых историй.

Алгоритм агента:
1. Определить текст, профиль, язык и подготовить ровно один JSON.
2. Одна заявка GitHub Issue с `STORY:`, body = JSON.
3. Проверить, что Issue закрыта автоматизацией с комментарием
   `Story inbox accepted`, и рассказ присутствует по ID в
   `live-content/content/stories.json`; без этого не говорить «готово».
4. Сообщить статус публикации отдельно от факта появления на телефоне.
   Для первого перехода на единый feed нужен соответствующий APK.
   После сброса базы телефон может запретить повторный импорт.

Код приложения обновлять только в `codex/android-v1`, подписанный APK
публикуется после CI в `phone-builds`. Не удалять APK и не сбрасывать базу.
Карточки используют другие пути и НЕ относятся к этому протоколу.

## ЖЁСТКОЕ ПРАВИЛО: ОДИН РЕПОЗИТОРИЙ, ТРИ ОТДЕЛЬНЫХ ПОЛНЫХ СЛОВАРЯ

**Единственный репозиторий:** `agurkin2021-gif/Language-learning`.
**Никаких новых репозиториев для архива не создавать.**
Ветка `live-content` содержит шесть канонических текстовых файлов:
- `content/papa/vocabulary-es.json`, `content/papa/vocabulary-en.json`;
- `content/mama/vocabulary-es.json`, `content/mama/vocabulary-en.json`;
- `content/dima/vocabulary-es.json`, `content/dima/vocabulary-en.json`.

Это **полные персональные словари профиля**: слова, устойчивые выражения,
русский перевод, статус `mastered` и служебные ревизии, включая
`deleted=true` для удалённых карточек. Для каждой пары профиль/язык
отдельный файл. Никогда не смешивать профили или языки.

**До любого изменения новых карточек и создания рассказов:**
1. Читать соответствующий `vocabulary-<language>.json` из `live-content`.
   Отсутствие файла, пустой ещё не синхронизированный архив или ошибка
   чтения — НЕ основание утверждать, что полный словарь уже проверен.
2. Для новых слов и фраз сверять ВСЕ записи `items`, включая
   `mastered=true`. Сравнивать нормализованный Unicode, регистр,
   пробелы и тип карточки; не возвращать уже освоенное в изучение,
   не восстанавливать `deleted=true`.
3. При создании рассказа использовать знакомую лексику именно выбранного
   профиля, учитывать освоенные слова и обучающие фразы и не приписывать
   другому профилю чужой словарь. Рассказ направлять ТОЛЬКО через STORY INBOX,
   как требует раздел выше.
4. Все записи Android в канонический архив синхронизируются **в обе стороны**
   через `PrivateVocabularySync` (старое имя класса), каждые ~15 минут
   при доступной сети и после изменений. Слияние по `revision`/`origin`
   с tombstones и GitHub SHA compare-and-swap: нельзя слепо
   перезаписывать чужую новую редакцию. Офлайн — отложенная синхронизация,
   а не обещание немедленного совпадения.
5. Для операций с теми же файлами из других клиентов используются
   `scripts/sync_papa.py`, `scripts/sync_mama.py`,
   `scripts/sync_dima.py`, общее ядро `scripts/profile_vocabulary_sync.py`.
   Перед публикацией новых карточек использовать
   `scripts/vocabulary_filter.py` для проверки полного архива.
6. В публичный репозиторий не помещать токены, пароли, данные устройств или
   приватные истории; полный личный словарь, помещённый по этому запросу
   в **публичный** `Language-learning`, доступен любому посетителю GitHub.
   Токен хранить только в Keystore Android и переменных окружения клиента,
   не в чате и не в GitHub Issue.

**Запрет упрощения:** нельзя подменять полный архив файлом
`content/<profile>/cards-es.json`, `DefaultCards.java` или ограниченными
списками; они не содержат всего изученного. Пользовательская SQLite-база
на телефоне остаётся источником первоначального наполнения шести файлов.
Пока телефон не отправил полную базу, шесть пустых файлов — только
заготовки и не подтверждают полноты.
