# CARD INBOX — ОБЯЗАТЕЛЬНЫЙ ЕДИНСТВЕННЫЙ ВХОД ДЛЯ СЛОВ И УСТОЙЧИВЫХ ФРАЗ

**Если пользователь просит добавить слово, карточку, выражение, глагольную конструкцию или скопировать карточки в другой профиль — немедленно включить CARD INBOX.** Это правило имеет приоритет над устаревшими советами о прямой записи в JSON. Даже если агент начал по неправильному пути: остановить прямую запись, вернуться к этой инструкции, оформить одну заявку через Issue. Никаких альтернативных направлений.

Владелец/репозиторий: `agurkin2021-gif/Language-learning`.
**Один вход:** GitHub Connector `create_issue` в этом репозитории, заголовок `CARD: <тема>`, body = **один JSON-объект, без Markdown**.

Пример для одного профиля:
```json
{
  "profile": "mama",
  "language": "es",
  "items": [
    {"type": "phrase", "spanish": "No lo sabía", "meaning": "Я этого не знала"},
    {"type": "word", "spanish": "recuerdo", "meaning": "я помню", "category": 1}
  ]
}
```
Для двух или трёх профилей в ОДНОЙ заявке: заменить `"profile": "mama"` на `"profiles": ["papa", "mama"]`. Категория обязательна только для слов: 1 — глагол, 2 — существительное, 3 — прилагательное. `type=phrase` означает устойчивое выражение или короткую разговорную конструкцию с переводом; `type=word` — одиночное слово. Поле `spanish` также используется для английского, когда `language=en` (схема приложения). Максимум 100 карточек за заявку.

**Никогда не выдумывать профиль.** `papa`, `mama` и `dima` — строго отдельные данные. Если пользователь явно перечислил несколько профилей — указать их в `profiles`. Язык `es|en` определять из запроса; не подменять один другим.

**Выход определяется только валидатором, НЕ агентом:** Workflow `.github/workflows/card-inbox.yml` в `main` запускает `live-content/scripts/card_inbox.py` и публикует по карте `content/<profile>/cards-<language>.json` **только в ветку `live-content`**. Workflow допускает заявки только от владельца репозитория; проверяет профили, язык, формат, переводы, дубль в опубликованном feed и известные записи полного словаря (включая `mastered` и `deleted`). Генерирует стабильные ID, повтор заявки не создаёт дубли. Исходные файлы не переписываются при ошибке валидации. В случае некорректного запроса — исправить ту же Issue, не создавать второй маршрут.

**Запрещённые обходы:** напрямую менять `content/*/cards-*.json`, `content/*/vocabulary-*.json`, `content/live_content.json`, `DefaultCards.java`, `BeginnerCards.java`, `main`, `codex/android-v1`; писать в `STORY INBOX`; создавать новый репозиторий; заменять имеющиеся карточки целиком новым списком.

**Обязательная проверка:** после создания Issue проверить, что она закрыта с комментарием `Card inbox accepted`, и запись появилась в нужном `live-content/content/<profile>/cards-<language>.json` (или результат `EXISTING`/`DELETED_BLOCKED`). При неуспехе нельзя говорить «сохранено» и нельзя обходить воронку прямой записью. Подтверждать отдельно публикацию в GitHub и импорт на телефоне.

**Ограничение полноты:** `vocabulary-<language>.json` — личный полный архив синхронизации Android, **не канал новых карточек**. Пока он пуст, нельзя утверждать, что проверены все существующие и освоенные карточки телефона. `cards-<language>.json` — только входящий учебный feed. Никогда не затирать архив карточками. Публичные Issue не должны содержать токены, приватные данные или полный личный словарь.

**Рассказы по-прежнему только через STORY INBOX ниже.** Протоколы независимы. Точка входа для карточек = `CARD:`; для рассказов = `STORY:`.

# ЕДИНСТВЕННЫЙ ПУТЬ ДЛЯ РАССКАЗОВ — STORY INBOX

**При любой команде «добавь/отправь рассказ» создавай ровно ОДНУ заявку GitHub Issue.**
Репозиторий: `agurkin2021-gif/Language-learning`. В GitHub Connector
вызывай `create_issue` с названием `STORY: <title>` и телом из **ОДНОГО JSON**,
без Markdown и без обрамляющих кавычек.

Обязательные поля JSON:
```json
{
  "profile": "papa",
  "language": "es",
  "title": "Un día",
  "spanish": "Hola. Chau.",
  "russian": "Привет. Пока."
}
```
`profile` строго `papa|mama|dima`; `language` строго `es|en`.
При EN английский текст также помещается в поле `spanish`, согласно текущей
схеме SQLite. Русский перевод обязателен. Можно передать `id`, если известен.
Не гадать профиль/язык, когда из контекста нельзя однозначно установить их.
Не класть в публичную заявку приватные данные, токены, словарь, прогресс.

**НЕЛЬЗЯ ПИСАТЬ В STORY FEED НАПРЯМУ.** GitHub Actions
`.github/workflows/story-inbox.yml` из default-ветки `main` принимает только
заявки с префиксом `STORY:`, созданные владельцем репозитория; сам вызывает
`live-content/scripts/story_inbox.py add`, валидирует и пишет ТОЛЬКО
`live-content/content/stories.json` (единый файл для всех профилей/языков).
Проверки: schema, лимиты, совпадение количества Android TTS фрагментов с
переводом, уникальность, идемпотентность. Заявка закрывается после успеха.
Если Action не запустилась или упала, НЕ утверждать «рассказ добавлен».

**СТРОГО ЗАПРЕЩЕНО** помещать новые рассказы в
`content/live_content.json`, `content/papa/stories-es.json`,
`content/<profile>/stories-<language>.json`, `content/stories-es.json`,
`main` или `codex/android-v1`. Старые файлы используются только
старыми версиями APK, но не являются входами новых историй.

Алгоритм агента:
1. Определить текст, профиль, язык и подготовить ровно один JSON.
2. Одна заявка GitHub Issue с `STORY:`, body = JSON.
3. Проверить, что Issue закрыта автоматизацией с комментарием
   `Story inbox accepted`, и рассказ присутствует по ID в
   `live-content/content/stories.json`; без этого не говорить «готово».
4. Сообщить статус публикации отдельно от факта появления на телефоне.
   Для первого перехода на единый feed нужен соответствующий APK.
   После сброса базы телефон может запретить повторный импорт.

Код приложения обновлять только в `codex/android-v1`, подписанный APK
публикуется после CI в `phone-builds`. Не удалять APK и не сбрасывать базу.
Карточки используют другие пути и НЕ относятся к этому протоколу.
