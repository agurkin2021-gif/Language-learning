# GPT-посредник для Android-приложения — автоматический обмен

Скрипт: `bridge/chatgpt_broker.py`. Он работает **только с официальным OpenAI API**. Это не неофициальный доступ к сайту ChatGPT и не обход Subscription Sharing. Для этой функции нужна отдельно оплачиваемая API-учётная запись. Подписка ChatGPT Plus не покрывает вызовы API. Оставленный в приложении режим «Обычный ChatGPT» работает по-прежнему, но без полной автоматизации.

## Как работает

1. Пользователь вводит тему рассказа, точную словоформу или обычный вопрос в **существующее** текстовое поле Android-приложения и нажимает **существующую** кнопку «Обычный ChatGPT». Новых кнопок и секций нет.
2. Android отправляет по HTTPS задачу и до 180 карточек **своего** текущего локального словаря на свой сервер-посредник. Отдельные телефоны и ES/EN не смешиваются.
3. Сервер отправляет запрос в официальный OpenAI Responses API (ключ находится **только на сервере**, не в APK).
4. GPT формирует рассказ и русский перевод, перевод точной словоформы либо обычный текстовый ответ (для обычного ответа карточки не создаются).
5. Посредник выполняет **три отдельных обращения к модели**:
   - 1/3: дословная точность и точная форма;
   - 2/3: грамматика, включая аргентинское voseo;
   - 3/3: независимая смысловая сверка и пропуски.
6. Если хотя бы один аудит не прошёл, ничего не сохраняется. Нет «автоматической подмены перевода» без повторной проверки.
7. Android получает результат с тремя отметками аудита; дополнительно проверяет язык, формат, количество предложений и дубликаты. После успеха SQLite сохраняет рассказ либо изучаемое слово; окно «РАССКАЗ ГОТОВ». Работает прямо в приложении: без переключения на браузер и без копирования.

Три аудита **снижают риск**, но не гарантируют абсолютной точности: модель может ошибаться во всех трёх проверках. Особенно важно выборочно проверять учебные слова и устойчивые выражения.

## Запуск на собственном VPS

Используются только стандартные библиотеки Python 3.10+.

Пример переменных окружения (значения — ТОЛЬКО на VPS, не в GitHub):
```
OPENAI_API_KEY=<separate_openai_api_key>
STUDY_BROKER_TOKEN=<random_string_from_openssl_rand_hex_32>
OPENAI_MODEL=gpt-4.1
STUDY_BROKER_BIND=127.0.0.1
STUDY_BROKER_PORT=8765
```
Запуск `python3 bridge/chatgpt_broker.py`. Скрипт слушает только loopback по умолчанию; для Android нужен публичный HTTPS-вход (например, Caddy с доменным именем `study.example.com`, проксирующий `127.0.0.1:8765`). Не открывать `8765` наружу по HTTP.

Пример Caddyfile при уже настроенном DNS:
```
study.example.com {
    reverse_proxy 127.0.0.1:8765
}
```

В приложении **долго нажать уже существующую кнопку «Обычный ChatGPT»** (новые кнопки и элементы интерфейса не добавляются) и указать `https://study.example.com` и собственный `STUDY_BROKER_TOKEN`. **Не вводить OpenAI API key в Android**.

Тесты без API и платежей: `python3 -m unittest discover -s bridge -p 'test_*.py' -v`.
Проверка серверного процесса: `curl http://127.0.0.1:8765/health`.

## Защита данных и ограничения

- Установить приложение/скрипт и настроить URL недостаточно: **пока на сервере нет `OPENAI_API_KEY`, отправка не выполняется**. Код не покупает кредиты и не инициирует платежи.
- Токен посредника хранится в приватных Android SharedPreferences. Не публикуйте его. Для большего уровня безопасности можно перенести его в Android Keystore; OpenAI API key уже изолирован на сервере.
- В посреднике нет постоянного журнала слов или содержания запросов. Результат хранится в памяти до 1 часа; затем удаляется. На сервере OpenAI действуют его собственные правила хранения и передачи данных.
- Скрипт не использует cookies, пароли от ChatGPT, автоматизацию веб-сайта или неофициальные endpoints.
- Лимиты, стоимость, доступность модели и API определяются провайдером. **Безлимитный GPT без API и без квот не создаётся скриптом-посредником.**
- Android требует **HTTPS**. DNS, VPS, выпуск TLS-сертификата и API-ключ должны быть настроены отдельно владельцем.
- Вариант `word` сохраняет одно точное слово; выражения имеют отдельную кнопку. Словарь и рассказ пользователя передаются в выбранный сервер только после нажатия кнопки.
- Отдельный инструмент формирования изображений для новых слов не входит в этот посредник; если для новой карточки обязательно изображение, добавление карточки необходимо расширить отдельным проверенным шагом.

## Состояние

Файлы проекта и автоматические тесты не означают, что создан публичный сервер. **Без сервера и отдельной API-учётной записи полный автообмен не запустится.** Чтобы протестировать на настоящем телефоне, нужен HTTPS-адрес посредника, его токен и серверный OpenAI API key.

## Требование: без визуальных изменений

Убраны добавленные в предыдущей итерации кнопки и блоки. Остаются все прежние тексты кнопок, их размещение и прежнее окно ChatGPT. Однократная настройка посредника доступна только долгим нажатием на **существующую** кнопку «Обычный ChatGPT». Обычное нажатие отправляет задание через посредник только когда сервер настроен; иначе вызывается прежний ручной способ открытия обычного ChatGPT, никаких скрытых платежей нет.

Команды «Добавь слово: <точная форма>» или «Добавь выражение: <точная форма>» обрабатываются как новые карточки с тремя аудитами. Просьбы о рассказах направляются в режим истории. Остальное поступает как обычный диалог и сохраняет короткий контекст на устройстве по каждому языку; обычные ответы не добавляют карточек без проверки. Автоматическое пакетное добавление 10 новых слов с подбором иллюстраций ещё не реализовано: исходные кнопки-пресеты остаются видимыми, но текстовое общение пока не означает подтверждённое пакетное сохранение.


## Запуск через Docker Compose и HTTPS (без правок интерфейса)

На **собственном** VPS (с установленными Docker Engine + Compose Plugin и DNS-записью A, указывающей на VPS):

```bash
cd bridge
cp .env.example .env
chmod 600 .env
# Заполните .env: реальный STUDY_DOMAIN, собственный случайный токен
# STUDY_BROKER_TOKEN (например, openssl rand -hex 32)
# и отдельно оплачиваемый OPENAI_API_KEY.
# НЕ коммитьте .env, НЕ отправляйте ключ API в чат.
docker compose config --quiet
docker compose up --build -d
docker compose ps
```

HTTPS автоматически обеспечивает контейнер Caddy, порты **80/443** должны быть доступны для входящих подключений. Python-посредник доступен только во внутренней сети Docker, без публичного HTTP-порта. `bridge/.env` исключён из Git через `.gitignore`.

Проверка доступности (без API-расходов): `curl -fsS https://ВАШ-ДОМЕН/health` — ответ `status: ok`, `api_configured: true` после настройки ключа. Установка Docker, настройка домена, VPS и секретов не выполняются ни GitHub Actions, ни Android-приложением автоматически.

### Голос и история чата

При подключённом посреднике существующая кнопка микрофона использует Android SpeechRecognizer, не Subscription Sharing. Сомнительный текст остаётся в прежнем поле для ручной проверки, точные распознанные запросы отправляются через ту же внутреннюю кнопку. Текстовые ответы ChatGPT озвучиваются штатным голосом Android. История короткого диалога сохраняется **локально** по языку и восстанавливается при повторном открытии того же окна, без дополнительного элемента интерфейса и без прямого доступа к истории из веб-сайта ChatGPT.

При отсутствии настроенного посредника сохраняется прежний режим открытия сайта ChatGPT; полностью автоматического обмена в нём нет.

### Проверка обмена без оплаты

В CI есть loopback-интеграционный тест: `POST /v1/jobs` → промежуточный статус → три аудита → `GET /v1/jobs/<id>` → ответ, с фальшивой моделью, которая **не** отправляет запросов в OpenAI. Это тест протокола, не реального качества GPT и не доказательство, что публичный сервер уже работает.
