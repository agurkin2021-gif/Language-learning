## Как видеть изменения

Каждая правка в открытом PR запускает проверку и новую сборку. После успешных проверок настроенный канал телефона подписывает release APK постоянным ключом и сохраняет его в выделенной ветке `phone-builds` этого публичного репозитория. APK и открытая информация о версии доступны без входа в GitHub. Артефакты GitHub Actions — отдельный механизм; для их скачивания через интерфейс нужен вход.

В приложении снизу видна версия `0.1.N-test`, где N — номер запуска GitHub. «Автообновления» показывает состояние и открывает однократное разрешение Android на установку из этого приложения. После разрешения приложение само проверяет канал при открытии и в фоновых заданиях, получает новую версию и проверяет APK. Для загрузки не нужны браузер, аккаунт или GitHub-токен. Нажатие на номер версии открывает сведения о коммите и ссылку на его проверку.

Установка ждёт перехода из приложения: полный APK update может завершить его процесс. Карточки, позиция и черновик новой карточки сохраняются до этого перехода. После обновления приложение нужно открыть снова. Это автоматическое получение и установка новой версии, а не мгновенная подмена открытого экрана. Фоновые проверки выполняются по расписанию Android и могут задерживаться; без сети продолжает работать установленная версия.

На Android 12+ используется системный режим self-update без обычного подтверждения каждой версии. Приложение обрабатывает и случай, когда Android всё же требует подтверждение: состояние видно в «Автообновлениях», системный запрос открывается по явному действию пользователя. На старых версиях Android нельзя обещать установку без подтверждения. На физическом телефоне этот путь должен быть проверен отдельно. Debug APK не подключается к публичному каналу обновлений.

Перед установкой проверяются размер загрузки, SHA-256, реальный package, возрастающий versionCode и подпись APK относительно установленного приложения. Несовпадение или обрыв загрузки оставляет текущую версию без изменений. Одних полей из сетевого JSON для доверия к APK недостаточно.

Постоянный ключ для канала телефона подготовлен отдельно. В репозитории хранится только публичный SHA-256 сертификата (`config/phone-signing.sha256`). Сам ключ и пароли передаются сборке через один Repository Actions Secret `ANDROID_SIGNING_CONFIG`; без него подписанный APK и ветка с обновлением не создаются. Первичное добавление этого секрета и установка на телефон должны быть подтверждены отдельно по факту. Во всех обновлениях сохраняются `applicationId`, сертификат и возрастающий `versionCode`. Учебные данные остаются на телефоне и не синхронизируются с GitHub.

`main` пока содержит исходный README: реализация находится в draft PR; автоматический merge не настроен.

Личное приложение с русским интерфейсом, Android 8.0+ (API 26). Два раздела: **Карточки** и **Рассказы**. Видео отсутствует.

## Что работает

- Добавление испанских слов и устойчивых выражений с русским смыслом.
- Только кнопка **Знаю** перемещает карточку в освоенное. Ошибку можно исправить кнопкой «Вернуть к изучению».
- Карточки, библиотека и позиция рассказа сохраняются в SQLite. Настройки — в SharedPreferences. Данные остаются после перезапуска и обновления APK с той же подписью; удаление приложения/очистка данных удаляет их. Облачное резервирование отключено.
- Именованная библиотека с одним явно подписанным, заранее написанным примером рассказа.
- Список рассказов отображается компактными строками. Нажатие на название открывает проигрыватель; крестик справа запрашивает подтверждение, затем удаляет только выбранный рассказ. Удалённые синхронизированные рассказы автоматически не восстанавливаются.
- Озвучивание установленным системным офлайн-голосом: приоритет es-AR, затем es-MX, затем другой es. Фактический язык показан в интерфейсе. Нет обещания аргентинского акцента при отсутствии голоса.
- Скорость именно речи 0.6–1.2×; большая кнопка паузы; повтор; режим одного предложения с ожиданием нажатия; непрерывный режим с паузами 0–5 секунд.
- Пауза прерывает речь немедленно. Продолжение повторяет прерванное предложение с начала (Android TTS не предоставляет надёжной паузы внутри аудио). После завершения предложения показывается следующее; кнопка повторения в ожидании повторяет предыдущее.
- При сворачивании, переключении экрана, потере аудиофокуса воспроизведение останавливается. Автоматического старта после возвращения нет. Запоздалые callbacks не переключают предложения.

## Что ещё НЕ реализовано

**Генерация рассказов помощником по освоенному архиву не подключена.** Приложение не читает этот чат и не имитирует генерацию шаблонами. `StoryGenerator` задаёт границу будущего адаптера: `Store.mastered()` → генератор → `Draft` → `StoryGenerator.save()` → та же библиотека. Сохранение и чтение результата реализованы и проверяются тестом, но самого генератора нет. Перед подключением нужно согласовать провайдера, способ авторизации, стоимость, передачу освоенных карточек и явно инициируемый пользователем запрос. Ключей генератора и платных API нет. Фоновая сеть используется только для обновлений приложения; карточки и рассказы в GitHub не отправляются.

Разрешение INTERNET используется для обновлений. Для речи выбираются только голоса, объявленные движком установленными и не требующими сети. Системный движок TTS — отдельное приложение: его корректность и политика обработки данных зависят от поставщика. При отсутствии офлайн-испанского звука будет показано объяснение; установка голоса выполняется пользователем в Android. Речь проверяйте на своём устройстве, особенно es-AR.

## Сборка и установка

JDK 17, Android SDK platform 35, build-tools 35.0.0, Gradle 8.9 (wrapper), Android Gradle Plugin 8.7.3.

```sh
sdkmanager 'platforms;android-35' 'build-tools;35.0.0'
./gradlew --no-daemon testDebugUnitTest lintDebug assembleDebug assembleDebugAndroidTest
```

Локальный `app/build/outputs/apk/debug/app-debug.apk` предназначен для разработки и эмулятора. Для телефона используется только `SpanishLearning.apk` из ветки `phone-builds`: он имеет постоянную подпись. Постоянная ссылка для первой установки:

`https://github.com/agurkin2021-gif/Language-learning/raw/refs/heads/phone-builds/SpanishLearning.apk`

Для первой установки пользователь открывает APK и подтверждает установку Android. Затем в самом приложении один раз разрешает ему установку обновлений. Следующие APK получает само приложение. Вход в GitHub на телефоне не требуется. Версия `0.1.5-test` ещё содержит старую кнопку внешней ссылки: для перехода к самообновлению её сначала нужно один раз обновить до версии с обновлятелем.

Старые APK, включая `0.1.4-test`, подписывались временным debug-ключом. Новый постоянный ключ не может обновить такой APK поверх: Android отклонит несовместимую подпись. Не удаляйте приложение с нужными данными ради установки новой сборки. При первой установке сразу используйте сборку с постоянной подписью. После настройки ещё требуется фактическая проверка обновления на телефоне: две последовательные версии, установка второй поверх первой и сохранение карточек, архива и рассказов.

## Однократное включение канала телефона

В Settings → Secrets and variables → Actions добавьте Repository Secret с именем `ANDROID_SIGNING_CONFIG`. Его значение — содержимое отдельно переданного файла конфигурации подписи. В нём находятся `keystore_base64`, `store_password`, `key_alias`, `key_password`. Этот файл является резервной копией ключа: храните его приватно, не добавляйте в Git, Issues, комментарии или артефакты сборки. Base64 — кодирование, не шифрование.

После добавления секрета нужно повторно запустить соответствующую проверку или отправить следующий коммит. Само добавление Secret не запускает сборку. Задание публикации проверяет сертификат, актуальность ветки и номер версии; ключ существует только во временном каталоге runner. В ветку доставки попадают только APK, контрольная сумма и открытые сведения о сборке. Секреты не включаются в APK.

Канал публикуется только из доверенной ветки `codex/android-v1` этого же репозитория через PR или из `main` после успешных проверок. Чужие fork PR и Dependabot не публикуют приложения. В `build-info.json` указан точный проверенный коммит исходников. Ветка доставки не содержит исходного кода или workflow; изменение APK не запускает новую сборку. Обновляется только её собственная история без force-push. Это не публикация в Google Play и не заявление о завершённости приложения.

Сборочный процесс повторяем по закреплённым версиям инструментов; побайтовая идентичность APK между машинами не заявляется. Wrapper проверяет SHA-256 дистрибутива Gradle.

## Проверка

`testDebugUnitTest`: разделение предложений, лимит длины, пустой текст, повторные нажатия, устаревшие callbacks, повтор, завершение, загрузка другого рассказа. `lintDebug`: статический анализ Android.

`connectedDebugAndroidTest` на устройстве/эмуляторе: SQLite после закрытия/открытия, независимость слов и выражений, явный архив/возврат, сохранение рассказа через границу генератора и позиции. Тест хранилища использует отдельную базу `test-learning.db`, не пользовательскую `learning.db`. Дополнительный инструментальный тест сохраняет PNG интерфейса в каталог приложения; workflow забирает их с эмулятора и прикрепляет к сборке.

Отдельное задание `self-update-test` на эмуляторе Android 14 собирает две версии с одной тестовой подписью. Первая версия через тот же `AppUpdater.installVerified()` устанавливает вторую. Проверка требует новый установленный versionCode, системный результат `STATUS_SUCCESS`, отсутствие ожидающего подтверждения и сохранение тестовых карточек, освоенного, рассказа, позиции и настроек в новом процессе. Прерывание старого процесса само по себе успехом не считается. Разовое разрешение установки задаётся только на одноразовом эмуляторе. Отчёт `self-update-reports-N` фиксирует фактический результат; публикация для телефона зависит от успешного прохождения этой проверки.

Ручная приёмка на телефоне: добавить слово и выражение, перезапустить, нажать «Знаю», проверить архив; открыть пример, проверить скорость, паузу посреди фразы, повтор, режим предложений и непрерывный режим; быстро нажимать кнопки, свернуть/повернуть экран, вернуться; проверить отсутствие самопроизвольной речи и сохранение позиции; проверить фактический акцент/офлайн-работу в авиарежиме.

API поведения TTS: [TextToSpeech](https://developer.android.com/reference/android/speech/tts/TextToSpeech), [Voice](https://developer.android.com/reference/android/speech/tts/Voice). Условия самообновления и завершения процесса: [PackageInstaller.SessionParams](https://developer.android.com/reference/android/content/pm/PackageInstaller.SessionParams#setRequireUserAction(int)).


## Синхронизация личного словаря с приватным GitHub

Один раз создайте **отдельный приватный репозиторий** на своём GitHub (например, `agurkin2021-gif/Language-learning-private`) с первоначальным README и выдайте приложению fine-grained personal access token с `Contents: Read and write` **только** для этого репозитория. В Android-приложении перейдите в «Настройки → Синхронизация словаря с GitHub» и заполните `owner/repo` и token. Токен не отправляйте в чаты и не включайте в публичные исходники. Он шифруется Android Keystore и сохраняется вне резервной копии телефона.

После настройки приложение автоматически выгружает **все** слова и устойчивые выражения со статусами освоения, русскими переводами и точными словоформами. Раздельные полные снимки для ES и EN записываются как `vocabulary/es-<device-id>.json` и `vocabulary/en-<device-id>.json`. Локальная SQLite остаётся первичной и работает офлайн. Если сервер недоступен, данные не удаляются, экспорт повторяется при следующем запуске/изменении. **Публичный** `Language-learning` не содержит личный словарь. Чтобы ChatGPT мог использовать приватные JSON при создании рассказов в диалоге, необходимо отдельно разрешить доступ GitHub-коннектору к этому приватному репозиторию.

Рассказы доставляются **без обновления APK**: достаточно добавить в `live-content/content/live_content.json` элемент `type=story` с уникальным `id`, полями `title`, `spanish` и `russian`. При следующем открытии приложения `RemoteContentSync` загрузит его в локальную библиотеку «Рассказы»; повторная загрузка и повторное появление удалённой истории предотвращаются `remote_items`. Если пользователь ранее сознательно нажал «Сброс базы», настройка `shared_content_disabled=1` продолжает запрещать автоматический импорт. Для нового режима синхронизации нужен **один первичный APK-апдейт**, но дальше ради новых рассказов переустановка не требуется.
